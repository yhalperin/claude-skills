# Jira Sprint Sync Skill

## Jira custom field IDs

```
Start Sprint:  customfield_21222  (cf[21222])
Finish Sprint: customfield_21223  (cf[21223])
```

## How to use

The user pastes a prompt generated by the PI board's **Export Jira Sync Prompt** button.
The prompt contains a Markdown table of changed epics and pre-formatted `jira_update_issue` calls.

## Steps

### 1. Parse the change table

Read the table from the user's message. It has this shape:

```
| Epic Key   | Summary          | Start Sprint         | Finish Sprint        |
|------------|------------------|----------------------|----------------------|
| JAG-1234   | Epic summary     | 27-Q1 Sprint 2       | 27-Q1 Sprint 5       |
| JAG-5678   | Another epic     | 27-Q1 Sprint 1       | 27-Q2 Sprint 1       |
```

Extract: `epicKey`, `startSprintName`, `finishSprintName` for each row.

### 2. Call jira_update_issue for each epic

For each row, call `jira_update_issue` via the `user-policy-broker` MCP:

```
jira_update_issue(
  issue_key: "<epicKey>",
  fields: {
    "customfield_21222": "<startSprintName>",
    "customfield_21223": "<finishSprintName>"
  }
)
```

Process all updates. Collect results (success / error per epic).

### 3. Report results

Present a completion table:

```
Jira Sprint Sync — Results

Group: Commerce ART  |  PI: 27-Q1
Updated: X / Y epics

| Epic Key   | Summary          | Start Sprint   | Finish Sprint  | Status  |
|------------|------------------|----------------|----------------|---------|
| JAG-1234   | Epic summary     | 27-Q1 Sprint 2 | 27-Q1 Sprint 5 | Updated |
| JAG-5678   | Another epic     | 27-Q1 Sprint 1 | 27-Q2 Sprint 1 | Updated |
```

If any updates failed, list the errors and suggest checking field permissions or Jira connectivity.

## Notes

- The skill only updates `customfield_21222` (Start Sprint) and `customfield_21223` (Finish Sprint).
  It does not change issue status, assignee, or any other field.
- Sprint field values are set as plain text strings matching Jira's sprint name format
  (e.g. "27-Q1 Sprint 3"). Ensure these match the exact sprint names in your Jira instance.
- If a field update fails with a 400 error, the sprint name may not match — check the
  sprint names in the board header against the actual Jira sprint names.
